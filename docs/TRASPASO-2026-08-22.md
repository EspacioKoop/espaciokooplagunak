## Trampas que costaron tiempo, para no repetirlas

- **`git merge-base --is-ancestor` no ve un squash-merge.** Una rama mergeada
  así deja de ser ancestro y parece huérfana para siempre. Usar `git cherry`,
  que compara por parche. Y para saber si una rama aporta algo, comparar
  **contenido** de fichero, no commits.
- **`gh api` escribe el JSON de error en `stdout`.** Sin mirar el código de
  salida, un 404 se lee como respuesta válida. Eso hizo decir que `main` estaba
  protegido justo porque no lo estaba.
- **Un check con filtro `paths:` sale `skipping`, y `skipping` nunca reporta
  éxito.** Exigirlo bloquea el repositorio.
- **`node --test foundry-module/tests/` sin el glob falla siempre.** El bueno es
  `node --test foundry-module/tests/*.test.mjs`.
- **401, 403, 405 y 429 significan que el endpoint EXISTE** (pide clave, pide
  POST, está ocupado). Solo 404 y «sin respuesta» son URL falsa.
- **`git add -A` barre lo que no miras.** Cinco ficheros de caché se colaron así
  en un PR.

Una skill recién aprendida es una hipótesis. Un test que no puede fallar no es
un test. Un número sin el comando que lo produce es un invento. Y una revisión
que empieza leyendo la conclusión del autor devuelve la conclusión del autor.
